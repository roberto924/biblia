# capa-ia — plan de construcción (fases 1–3 del diseño)

> **Para agentes:** SUB-SKILL OBLIGATORIA: `superpowers:subagent-driven-development` (recomendado) o
> `superpowers:executing-plans`, tarea por tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** un repo `C:\PROYECTOS IA\capa-ia` con la capa de IA local: el motor de Orchestrator copiado y
recortado, la elección de proveedor por equipo y cuota, trabajos de texto e imagen, registro, CLI, HTTP local y
cliente Python, con gasto adicional cero.

**Arquitectura:** Node ESM sin dependencias. `src/nucleo/` es la copia recortada del motor (coste, entorno,
argumentos, lectura de salida, límite de uso). `src/proveedores/` adapta cada herramienta. `equipo`, `cuota` y
`elegir` deciden; `trabajos` ejecuta; `registro` anota; `bin/capa-ia.mjs` y `src/servidor.js` exponen.

**Stack:** Node ≥ 20 (instalado 24.15.0), `node:test`, `node:http`, `child_process`; Python 3 stdlib para el
cliente.

**Diseño:** `C:\PROYECTOS IA\Biblia\docs\superpowers\specs\2026-11-17-capa-ia-design.md` (en la tarea 1 se copia a
`capa-ia/docs/diseño.md`). Origen del motor: `C:\PROYECTOS IA\Orchestrator` (solo lectura: **no se modifica**).

El Estudio de la Biblia (fase 4) tiene su propio plan, que se escribe al cerrar la tarea 8 de este, cuando las
interfaces de la CLI ya están fijas.

## Restricciones globales

- Node ≥ 20, ESM (`"type": "module"`), **cero dependencias npm** (ni de desarrollo). Pruebas con `node --test`.
- Windows primero; todo lo específico de Windows va detrás de `process.platform === 'win32'`.
- **Gasto adicional cero:** nunca claves de API, créditos, recarga ni `account/rateLimitResetCredit/consume`;
  «UNKNOWN bloquea»; el hijo nunca hereda `OPENAI_*`, `CODEX_*`, `AZURE_OPENAI*`, `ANTHROPIC_*`, `CLAUDE*`,
  Bedrock/Vertex ni `*_API_KEY`/`*_TOKEN`/`*_SECRET`.
- **Las pruebas nunca gastan cuota:** solo ejecutables falsos y servidores falsos. Las pruebas reales están solo en
  la tarea 12 y cada una se anuncia al usuario antes.
- Nunca se leen credenciales (`~/.codex/auth.json`, `~/.claude/.credentials.json`) ni se pasa
  `forced_login_method` a Codex (cierra la sesión, medido 2026-10-06).
- HTTP solo en `127.0.0.1`, puerto por defecto 8780, token obligatorio; no imita la API de OpenAI ni Anthropic.
- Carpetas: datos en `%APPDATA%\capa-ia` (config, token, registro, caché, cuota de Claude); trabajos temporales en
  `%LOCALAPPDATA%\capa-ia\trabajos\<id>`. Ambas se pueden cambiar con la variable `CAPA_IA_HOME` (datos) y
  `CAPA_IA_TRABAJOS` (temporales): las pruebas siempre las apuntan a una carpeta temporal.
- Defaults del diseño: `tope_semanal_pct` 80 (rango 0–95); `costo_inicial` imagen 0,2, texto 0,05;
  `claude.lote_max` 5; `arrancar_locales` false; caché de equipo 10 min; margen de VRAM 1,5 GB.
- Textos para el usuario en español. Comentarios sin referencias a sprints, ADR ni «misión» de Orchestrator; las
  mediciones con fecha se conservan y se copian a `docs/reglas-medidas.md`.
- Commit por tarea en el repo nuevo (sin remoto; el push lo decide el usuario).

## Foco de revisión

1. Rutas con espacios y acentos (`C:\PROYECTOS IA\…`, `José`) en `adjuntos`, `salida` y `cwd`: deben funcionar
   (spawn con `shell:false`, sin comillas a mano). → prueba en tarea 7.
2. Codex instalado solo como `codex.cmd` de npm: se resuelve el `codex.exe` real de
   `node_modules\@openai\codex\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\`, o el de
   la app de escritorio en `%LOCALAPPDATA%\OpenAI\Codex\bin\`. → prueba en tarea 2.
3. Dos apps (o dos procesos de la CLI) lanzan a la vez al mismo proveedor: un bloqueo por archivo serializa
   (`%APPDATA%\capa-ia\bloqueos\<proveedor>.lock`, con pid y hora; uno huérfano de un pid muerto se libera). →
   prueba en tarea 7.
4. La cuota de Codex no se puede leer (app-server no responde o falla): Codex queda **no elegible** salvo que haya
   una lectura de menos de 10 min en caché. → prueba en tarea 6.
5. Codex termina con código 0 pero no dejó PNG válido, o `salida` ya existe: `fallo` con motivo, no se copia
   nada y nunca se sobrescribe salvo `sobrescribir: true`. → prueba en tarea 7.
