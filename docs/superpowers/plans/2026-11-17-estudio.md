# Estudio de la Biblia narrada — plan de construcción (fase 4 del diseño)

> **Para agentes:** SUB-SKILL OBLIGATORIA: `superpowers:subagent-driven-development` (recomendado) o
> `superpowers:executing-plans`, tarea por tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** una herramienta local del repo de la Biblia donde se ven láminas, hojas, tomas, prompts e imágenes
con su revisión, y desde donde se genera (vía capa-ia), se aprueba o rechaza, se edita el prompt y se regenera.

**Arquitectura:** `herramientas/imagenes.py` (qué falta y cómo se pide, delegando en capa-ia) +
`herramientas/estudio_datos.py` (lectura, revisión y edición de fuentes, sin red) + `herramientas/estudio.py`
(servidor HTTP stdlib en 127.0.0.1:8766 con API JSON y el lote) + `herramientas/estudio/` (página HTML/CSS/JS sin
dependencias). Nada de esto se publica: la PWA, `sw.js` y GitHub Pages no lo tocan.

**Stack:** Python 3 stdlib (siempre `python -I`), JS/CSS sin dependencias, cliente Python de capa-ia.

**Diseño:** `docs/superpowers/specs/2026-11-17-capa-ia-design.md` §9, §9.1, §13.1 (y `C:\PROYECTOS IA\capa-ia\LEEME.md`
para la interfaz de capa-ia).

## Restricciones globales

- Python stdlib y `python -I`; JS/CSS sin dependencias ni build; textos de la interfaz en español.
- Servidor solo en `127.0.0.1:8766`; rechaza `Host` distinto de `127.0.0.1:8766`/`localhost:8766` (403); sin CORS;
  archivos servidos solo desde `herramientas/estudio/` y `guiones/imagenes/` (sin `..`, sin rutas absolutas).
- **Gasto:** toda generación pasa por capa-ia (`app: "biblia"`, `capa-ia.json` en la raíz del repo); nunca se
  llama a `codex` directamente. Las pruebas usan un `capa_ia` falso: **ninguna prueba genera ni gasta**.
- Importar capa-ia: `sys.path.insert(0, os.environ.get("CAPA_IA_REPO", r"C:\PROYECTOS IA\capa-ia") + r"\clientes\python")`.
- JSON de `guiones/fuentes`: se escriben con `json.dumps(obj, ensure_ascii=False, indent=2) + "\n"`, conservando el
  orden de claves; `estilo.json` conserva sus finales de línea CRLF. Nunca se reescribe un archivo si la validación
  falla.
- Validación de una edición: copiar `guiones/fuentes` a una carpeta temporal, aplicar el cambio y correr
  `python -I herramientas/guiones.py --fuentes <tmp> --sin-salida`; solo si sale 0 se escribe el archivo real y
  luego se corre `python -I herramientas/guiones.py` para regenerar las fichas `.md`.
- No se editan desde el Estudio: `base_imagen_en`, `negativo_en` de `estilo.json`, `base_movimiento_en` (cambian el
  estilo de todo; diseño §13.1).
- Rótulo en toda imagen generada mostrada: «Ilustración moderna (generada con IA)» (`estilo.json → rotulo_ia`).
- Pruebas: cada script trae `--autoprueba` (convención del repo) con fixture en carpeta temporal; además
  `node pruebas/probar.mjs` debe seguir en verde.
- Commits por tarea en `main` (el repo de la Biblia trabaja en main); sin push.

## Foco de revisión

1. Rutas con espacios y acentos (`C:\PROYECTOS IA\…`, ids como `jose`, nombres con «é»): servir imágenes, mover a
   `_anteriores/`, escribir JSON. → autoprueba de la tarea 2.
2. Edición concurrente: dos guardados seguidos del mismo prompt, o editar mientras corre el lote: el archivo nunca
   queda a medio escribir (escritura atómica tmp + replace) y el lote usa el prompt vigente al empezar cada imagen.
   → tareas 2 y 3.
3. Regenerar una imagen cuya generación falla: la anterior no se pierde (sigue en `_anteriores/` y la tarjeta lo
   dice). → tarea 2.
4. capa-ia devuelve `esperando_cuota` o `bloqueado_coste`: el lote para y la página muestra el motivo y la hora de
   reinicio, sin reintentar. → tarea 3.
5. Una imagen cambia en disco (regenerada o reemplazada a mano): su revisión vuelve a «pendiente de revisar» por el
   `sha256`. → tarea 2.

**Archivos:**

- Modificar: `CLAUDE.md` (línea de imágenes: `python -I herramientas/imagenes.py --generar N`, vía capa-ia, y el
  Estudio `python -I herramientas/estudio.py`), `guiones/LEEME.md` (flujo con capa-ia y el Estudio)

**Interfaces:**
- Produce (se mueven tal cual desde `imagenes_codex.py`): `leer(p)`, `png(p) -> (ancho, alto) | None`,
  `lamina(nombre) -> Path | None`, `prompt_imagen(E, prompt_en, negativo_en="") -> str`, `instrucciones() -> str`,
  `pendientes(E) -> list[dict]` (cada uno `{id, destino, hoja, prompt, refs, bloqueo}`; sin filtrar por existencia).
- `NO_REPETIR = "Use the attached style reference panels only for line work, cel shading and palette: do not reuse their composition, objects, trees, buildings or layout."`
- `texto_pedido(t, instr) -> str`: instrucciones de dirección de arte + `NO_REPETIR` + el prompt de `t`; sin nada
  propio de Codex (rutas de guardado, CLI, claves: eso lo pone capa-ia).
- `trabajo_de(t, instr, sobrescribir=False) -> dict`: `{"app": "biblia", "tipo": "imagen", "prompt":
  texto_pedido(t, instr), "adjuntos": [str(r) for r in t["refs"]], "salida": str(t["destino"]), "etiqueta":
  t["id"], "ruta_app": str(RAIZ), "sobrescribir": sobrescribir}`.
- `generar_lote(n, solo=None, ejecutar=None, al_progreso=None, detener=lambda: False) -> list[dict]`: recalcula
  `pendientes` (solo los que no existen y sin bloqueo, filtrados por prefijo `solo`) en cada vuelta, manda **un**
  trabajo a la vez con `ejecutar` (por defecto `capa_ia.ejecutar`), llama `al_progreso(t, resultado)` y para en el
  primer resultado que no sea `ok` o cuando `detener()` dé True; devuelve los Resultados.
- `historial_viejo() -> list[dict]`: filas de `guiones/registro/imagenes.jsonl` con `origen: "codex directo
  (2026-11-16)"`, `prompt` reconstruido con la función `pedido_v1(t, instr)` (copia literal del `pedido` de
  `imagenes_codex.py`) solo si su `sha256[:16]` coincide con `prompt_sha256`; si no, `prompt: null` y
  `prompt_nota: "no se pudo reconstruir"`. No escribe en el registro de capa-ia (ver Ruling al final).
- CLI: `python -I herramientas/imagenes.py` lista; `--generar N [--solo PREFIJO]` genera vía capa-ia; código 1 si
  el lote paró por fallo, 2 si por cuota, 3 si por coste.

### Task 2: Capa de datos del Estudio

**Archivos:**
- Crear: `herramientas/estudio_datos.py`

**Interfaces:**
- Consume: tarea 1 (`pendientes`, `prompt_imagen`, `lamina`, `historial_viejo`).
- `REVISION = guiones/registro/revision.json` (`{id: {estado: "aprobada"|"rechazada", nota, fecha, archivo,
  archivo_sha256}}`), `ANTERIORES = guiones/imagenes/_anteriores/`.
- `datos(registro_capa=None) -> dict` para la página:
  `{estilo: {nombre, rotulo_ia}, laminas: [Item], personajes: [Item], escenarios: [Item], pasajes: [{libro, id,
  titulo, escenas: [{id, titulo, tomas: [Item]}]}]}` con
  `Item = {id, titulo, grupo: "estilo"|"personajes"|"escenarios"|"tomas", imagen: "/img/<ruta>" | null, ancho, alto,
  prompt_en, negativo_en, prompt_enviado (prompt_imagen completo), movimiento_en (solo tomas), ficha: {campos
  legibles: rasgos, vestuario, edades, texto, epoca, nota… los que tenga}, fuente: "<ruta relativa del JSON>",
  campo: "<ruta del prompt dentro del JSON, p. ej. hoja_referencia.prompt_en>", refs: [ids], bloqueo,
  revision: {estado: "pendiente"|"aprobada"|"rechazada"|"cambiada", nota, fecha}, historial: [filas], anteriores:
  ["/img/_anteriores/…"]}`. `historial` = filas del registro de capa-ia con `etiqueta == id` (de `registro_capa`,
  que el servidor pasa) + `historial_viejo()` del mismo id, por fecha.
- `marcar(id, estado, nota="") -> dict`: guarda en `revision.json` con `archivo_sha256` de la imagen actual; falla si
  no hay imagen. Al aprobar `estilo/patron-2-interior` cuando la imagen es `patron-2-interior-codex.png`, la
  renombra a `patron-2-interior.png` y lo dice en la respuesta.
- `estado_revision(id) -> str`: «cambiada» si el sha guardado no coincide con la imagen actual (foco 5).
- `editar_prompt(id, campo, valor) -> {ok, antes, despues, errores}`: `campo` ∈ `prompt_en` | `negativo_en`;
  resuelve el JSON y la ruta del campo (láminas: `estilo.json → laminas_patron[i].prompt_en`; hojas:
  `hoja_referencia.*`; tomas: `escenas[…].tomas[…].imagen.*`); valida como dicen las restricciones globales; si hay
  errores devuelve `{ok: false, errores: ["archivo · id · campo · msg", …]}` sin escribir; si no, escritura atómica
  y regeneración de fichas `.md`. Rechaza campos no editables con error.
- `apartar_para_regenerar(id) -> Path | None`: mueve la imagen actual a
  `_anteriores/<id con / → __>-<AAAAMMDD-HHMMSS>.png` y devuelve la ruta (foco 3).

  `cambiada`; `editar_prompt` con «halo» (palabra prohibida de `estilo.json`) → `ok: false`, archivo idéntico al
  original (bytes); con un texto válido → `ok: true`, el JSON cambia solo ese campo (comparar como dict) y conserva
  indentación 2, acentos literales y salto final; en `estilo.json` conserva CRLF; dos ediciones seguidas → la
  segunda ve la primera (foco 2); `apartar_para_regenerar` mueve y la imagen vieja queda accesible por
  `anteriores`; aprobar la lámina 2 renombra el archivo.

### Task 3: Servidor del Estudio y lote

**Archivos:**
- Crear: `herramientas/estudio.py`
- Modificar: `.claude/launch.json` (añadir `{"name": "estudio", "runtimeExecutable": "python", "runtimeArgs":
  ["-I", "herramientas/estudio.py"], "port": 8766}`)

**Interfaces:**
- Consume: tareas 1 y 2; cliente `capa_ia` (`estado`, `registro`, `ejecutar`, `modo`).
- `python -I herramientas/estudio.py [--puerto 8766] [--sin-capa]` (`--sin-capa`: no arranca capa-ia; para
  pruebas). Al arrancar: si `capa_ia.modo() == "cli"`, lanza `node <CAPA_IA_REPO>/bin/capa-ia.mjs servir` como
  proceso independiente (Windows: `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`, sin consola) y espera hasta 10 s a
  que `modo()` sea `"http"`; si no lo consigue, sigue en modo CLI y lo avisa en `/api/estado`. El token de capa-ia
  nunca se manda al navegador.
- Rutas (`ThreadingHTTPServer`, JSON UTF-8):
  - `GET /` y `/estudio/<archivo>` → estáticos de `herramientas/estudio/`.
  - `GET /img/<ruta>` → PNG de `guiones/imagenes/` (incluye `_anteriores/`); 404 si sale de esa carpeta.
  - `GET /api/datos` → `estudio_datos.datos(capa_ia.registro(app="biblia"))` (si el registro falla, `historial`
    solo con el viejo y `aviso`).
  - `GET /api/estado` → `{capa: "http"|"cli", cuota: {usado_pct, semanal_pct, reinicio_en, leida} de codex según
    `capa_ia.estado()`, gasto_biblia_semana_pct: Σ `costo_estimado` de las filas de la Biblia desde el último
    reinicio semanal (≈), tope_biblia_pct: 30, aviso?}`.
  - `POST /api/revision {id, estado, nota}` → `marcar`.
  - `POST /api/prompt {id, campo, valor}` → `editar_prompt`; 400 con `errores` si no valida; 409 si hay un lote en
    curso que tiene ese id como trabajo actual.
  - `POST /api/generar {n?, ids?, regenerar?: bool}` → arranca el lote en un hilo y responde 202; 409 si ya hay uno.
    Con `ids` + `regenerar`: para cada id, `apartar_para_regenerar` y genera ese id (orden dado); sin `regenerar`
    solo los pendientes. Con `n`: `generar_lote(n)`. Un id bloqueado se salta con motivo.
  - `GET /api/lote` → `{en_curso, actual: {id, desde}, hechas: [{id, estado, motivo, segundos, reinicio_en}],
    parado_por: null|"fallo"|"esperando_cuota"|"bloqueado_coste"|"detenido"|"terminado"}`.
  - `POST /api/lote/detener` → el lote termina tras la imagen en curso (Ruling: no se corta la imagen a medias).
  - Todo con comprobación de `Host` (403) y cuerpo JSON ≤ 64 KB (413).
- La página sondea `GET /api/lote` cada 2 s mientras haya lote.

  `Host: evil.com` → 403; `/api/datos` 200 con los grupos; `POST /api/prompt` inválido → 400 con errores; lote de 2
  con el falso → `/api/lote` termina con 2 `ok`; falso que devuelve `esperando_cuota` → `parado_por:
  "esperando_cuota"` con `reinicio_en` y una sola llamada (foco 4); `regenerar` de un id cuya generación falla →
  la imagen vieja sigue en `_anteriores/` y `datos()` la lista (foco 3); segundo `POST /api/generar` con lote en
  curso → 409.

## Rulings de este plan (decisiones del orquestador)

- El registro viejo (`guiones/registro/imagenes.jsonl`) **no se copia** al registro de capa-ia: el Estudio lo lee
  como historial «codex directo (16-nov)» — escribir filas ajenas en el registro de capa-ia mezclaría su costo
  estimado — si mal, el historial viejo no aparece en `capa-ia registro` (sí en el Estudio).
- «Detener» termina el lote tras la imagen en curso; no se cancela una imagen a medias (el cliente Python de
  capa-ia no expone cancelar) — si mal, hay que esperar hasta ~2 min a que termine la actual.
- Progreso por sondeo de `GET /api/lote` cada 2 s en vez de reenviar el SSE de capa-ia — más simple y sin exponer
  el token — si mal, el progreso llega con ~2 s de retraso.
- El Estudio arranca `capa-ia servir` si no está, para compartir cola y bloqueo con otras apps — si mal, queda un
  servidor de capa-ia corriendo en segundo plano (se para con `capa-ia parar`).
